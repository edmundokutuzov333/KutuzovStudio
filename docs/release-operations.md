# Release operations

Independent project only; no portfolio changes. Production branch main. Static CDN, Supabase public read-only catalog and optional private editorial API. No server compute for document creation. Git auto-deploy disabled: inspect Studio CI on exact main SHA and manually deploy that SHA only after all jobs (including release-artifact) succeed. The Vercel build repeats the unit suite and static build. Keep the previous READY deployment for rollback. No token in repository. The project is a free personal/non-commercial demonstration while on Vercel Hobby; commercial operation requires an eligible hosting plan/provider. No paid add-ons enabled.

Run npm test, npm run build, npm run preview. Build publishes only approved HTML, CSS, JS, icons, manifest and offline prepress tools. health.json reports static release availability and commit, not database health. Verify deployed health.json, index, admin noindex, CSP, missing-path 404, MIME types, remote catalog and anonymous Edge rejection. For a production domain, set STUDIO_PUBLIC_ORIGIN (HTTPS origin) or use Vercel production URL metadata; robots/sitemap generated only with valid origin. No analytics collecting personal data. Check provider usage dashboards before increasing quotas. Rollback: restore the last tested READY deployment from Vercel; do not roll back Supabase migrations destructively. Service workers update when all Studio tabs close, so save the local project before reloading. Physical print, real TOTP enrollment and Magnific authorization remain external gates.

## Production baseline
Verified independent hostname: https://kutuzov-studio.vercel.app. Initial release 7bbaf223659f7148cacdffd478348462d702651e passed all eight Studio CI jobs and was published as Vercel deployment dpl_3p3izR76KDwebpauqLoScjGiwp9v. Health, homepage, editor, static JS, sitemap and private-path 404 were verified through HTTPS. Monitoring runs daily at 06:23 UTC and can be dispatched manually; public HTTPS smoke and live Supabase checks are read-only. The browser check runs on monitor workflow changes and manual dispatch. Production canonical origin is a plain Vercel environment setting (not a secret). The same origin is used for CI release artifacts. All CI actions are pinned to exact commits, checkout credentials are not persisted. Review all jobs and deployment health before declaring any new revision released.

## Expanded production acceptance
The public browser test also exercises local project recovery after going offline, two actual badge PDFs in a ZIP, privacy reset and the unauthenticated editorial UI. The HTTP health probe validates the PWA manifest, public documentation, module MIME types, cache controls, canonical origin and sensitive build paths. This uses synthetic data in an ephemeral browser profile; it does not create real accounts or make provider requests.
